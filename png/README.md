# 人物素材入口

返回 [项目首页](../README.md)；离线生成和抠图见 [制作工具](../tools/liveportrait/README.md)。

## 网页实际使用的文件

| 固定名称 | 用途 |
| --- | --- |
| `avatar.png` | 静态图、视频 poster、播放失败时的回退图片 |
| `avatar.webm` | 可选动作视频，优先使用；透明人物推荐带 alpha 的 VP9 |
| `avatar.mp4` | 可选动作视频，仅在没有 WebM 时选用 |

网页不按 Grace / Liz / Newdata 子目录切换角色，也不需要修改旧的 `ACTIVE_CHARACTER` 配置。当前显示什么人物，以根目录固定文件内容为准。

## 替换步骤

1. 先把旧的固定 PNG 和视频复制到素材备份目录，保留原文件。
2. 将新图片和配套视频复制为上述固定名称；PNG 建议取同一视频第一帧。
3. 只有图片时移走旧的 WebM 与 MP4，否则网页仍会优先播放旧视频。
4. 刷新 HTTP 页面，无需重启后端。
5. 检查人物边缘、比例、眨眼首尾，以及视频失败时的静态回退。

文件需要是实际对应格式，改扩展名不会转换编码。MP4 眨眼片段本身不等于带透明度的视频，也不会自动得到语音口型。

## 尺寸与展示

当前没有强制正方形或统一图片分辨率。前端使用 `style.css` 的 `.stage`、`.avatar` 与 `.avatar-media` 控制舞台和媒体展示，媒体以 contain 保持比例；舞台尚不按素材比例自动改变。

制作时尽量让人物在视频中保持相同位置、尺寸和背景处理；单独生成多张不同服饰/头发的图片再轮播会出现跳变。图片与视频使用相同画幅，避免首帧和回退图切换时跳动。

视频播完后，`script.js` 的 `VIDEO_WAIT_MIN` / `VIDEO_WAIT_MAX` 控制下一次播放等待。后台、页面离开或“减少动画”设置会影响播放；这些状态不是素材缺失。

## 目录职责

- `Grace/`、`Liz/`：历史人物原始和加工素材，网页不自动选择。
- `Newdata/`：另一批人物的原始/加工素材；其中 `previous-avatar/` 保存一次替换前的固定素材备份。
- 其他制作目录：供人工或离线工具使用；最终展示仍复制到根目录固定入口。

不要根据子目录名称推断当前人物，也不要为换肤重新引入多套入口配置。

## 与其他功能的关系

替换素材只改变外观，不改变 Dify 人设、会话上下文、语音音色或音频缓存。图片本身不会自动眨眼；当前眨眼是视频内容，实时口型尚未实现。

后端仅允许已登记的素材类型，并检查路径留在素材目录内。固定三个入口可在运行时替换；其他素材路径通常在后端启动时登记，不应依赖新子目录文件立即可通过 HTTP 访问。
