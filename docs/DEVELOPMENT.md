# 开发与维护

先用 [README](../README.md) 启动项目；代码规范与必须保持的行为集中在 [AGENTS.md](../AGENTS.md)，不要在这里复制另一套规则。本文所有命令默认在项目根目录运行。

## 1. 按任务找到文件

| 需求 | 首先阅读或修改 |
| --- | --- |
| 页面结构、抽屉、开关 | `index.html`、`style.css`、`script.js` |
| 本地规则回答 | `script.js:getLocalReply` |
| 测试句与回答 | `test_cases.json` |
| 语音分句、缓冲、停止 | `speech.js:SpeechParts` / `ReplySpeech` |
| 音色或合成参数 | `tts.py:audio_profile` 与实际请求；同步页面音色文字 |
| Dify 地址、user、消息与停止协议 | `server.py:make_dify_request` / `stream_reply` / `stop_dify_task` |
| 缓存键、准备计划与路由 | `server.py:speech_key` / `test_audio_plan` / `test_request` |
| 数据库存储与容量 | `cache.py:AudioCache` |
| 人物更换与离线制作 | [素材入口](../png/README.md)、[离线工具](../tools/liveportrait/README.md) |

路径后面的函数名表示定位入口，不是文件名的一部分。先明确行为，再做最小修改；不要把环境、素材制作与网页运行混在一个环境中。

## 2. 本地迭代顺序

1. 确认工作目录和未提交改动，说明本次准备修改的行为。
2. 优先用开发测试模式复现 UI / 播放问题；普通模式用于确认真实模型链路。
3. 修改对应模块，保留可读注释和停止/失败路径。
4. 执行与修改相关的回归；使用模拟供应商和临时数据库。
5. Python 变动重启后端；网页代码变动刷新，避免旧页面继续运行旧 JS。
6. 对照下文人工清单，记录实际结果；接口、配置或行为变化同步更新文档。

测试模式没有云端兜底。普通模式和“生成缺失音频”仍可能产生服务用量，检查操作本身不会生成音频。

## 3. 自动化检查

### 后端回归

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p 'test_*.py'
```

| 文件 | 主要覆盖 |
| --- | --- |
| `tests/test_streaming.py` | Dify SSE、完成条件、停止确认/失败/竞争 |
| `tests/test_tts.py` | 上游音频协议、异常、首包提前发送、锁清理 |
| `tests/test_cache.py` | 持久化、参数失效、校验损坏、额度、严格未命中、准备和复用 |
| `tests/test_avatar.py` | 固定素材检测、增删替换、Range 与私有文件拒绝访问 |

使用临时本机服务与模拟供应商，不消耗云端额度。环境若限制回环网络，需要允许本机测试端口；不要改监听到公网绕过限制。

### 前端回归

需要支持测试所用 Web APIs 的 Node.js；本机已核对 v24.19.0：

```powershell
node tests/test_speech.cjs
node tests/test_frontend_streaming.cjs
```

前者覆盖流式音频、分句、预取、音频时钟、取消与预热；后者覆盖页面分支、任务竞争、会话隔离、素材回退及准备流程。它们使用模拟 DOM / 音频设备，不能替代真实浏览器的音质与可视验收。

### 本地 HTTP 诊断

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/diagnose_latency.py
```

默认进行30次模拟 JSON 聊天测量和15项接口/并发检查，只反映本机处理开销。当前诊断选取登记表的首个 WebM（目前为固定入口 `png/avatar.webm`），该文件需存在且可读取；只有图片/MP4或固定 WebM 缺失时，使用素材测试或浏览器验收，不能把诊断缺少素材误判为模型故障。

脚本不会测量网页的 Web Audio 开口时间，也没有覆盖全部缓存与 SSE 行为，需结合回归测试和页面计时。

`--live` 选项会额外发起两次真实 Dify 请求并创建会话、产生用量，不是日常回归的一部分。它采用独立诊断解析逻辑，不能替代主链路的流完成校验。本次文档维护没有执行该选项。

### 文档与差异检查

```powershell
git diff --check
git diff --stat
```

检查 Markdown 相对链接、文件名、代码围栏、命令参数、接口字段，以及“已实现 / 未实现 / 本次未验证”的区分。不要把旧行号或历史单次耗时写成长期保证。

## 4. 浏览器人工验收清单

修改涉及的功能逐项验证，不要求每次运行所有有用量的检查。

| 场景 | 预期结果 |
| --- | --- |
| 页面首次打开 | 模型、语音、开发测试均关闭，不自动发起云端生成 |
| 本地规则 | 无模型请求；当前回答和抽屉同步显示 |
| 模型流式回复 | 生成中正文逐步出现；非空完整结果才标记完成 |
| 模型停止 | 首字前可提出停止；确认失败可重试；部分文字保留 |
| 开发测试命中 | 返回固定回答，语音只用缓存，模型开关锁定 |
| 测试问答/音频未命中 | 明确提示，不请求 Dify 或豆包 |
| 准备音频 | 先显示缺失段数/字数，主动生成后才产生请求；重复准备跳过命中 |
| 停止准备 | 后续段不再发起；已完成项保留；可重新检查继续 |
| 缓存重启复用 | 重启后仍可播放；缺少密钥时命中也可用 |
| 朗读停止与新轮次 | 旧声音立即停止，旧回调不能启动新片段 |
| 开关中途变化 | 开启语音只读后续新内容；退出测试保留原 Dify 编号 |
| 人物素材 | 视频加载失败回退 PNG；背景和减少动画设置正确暂停 |
| 布局与键盘 | 窄屏无横向溢出；输入 Enter 发送；抽屉可开关并用 Escape 收起 |

真实模型/语音验收应记录环境、输入范围、用量是否发生与结果。模型生成慢和音频设备冷启动分开判断；不能将服务器首包当作用户已经听到声音。

## 5. 常见问题

| 现象 | 检查顺序 |
| --- | --- |
| 启动后立即返回“后端已经在运行” | 找原终端；日志留在原进程。Python 变更需 Ctrl+C 停止后重启 |
| 新按钮存在但 API 报错 | 先确认运行的是最新后端，而不是仅刷新了网页 |
| `file://` 页面不能连接 | 使用快捷方式或本机 HTTP 地址启动 |
| 模型503 / 502 | 核对 Dify 应用密钥、已发布版本与会话；不要把腾讯模型密钥填作应用密钥 |
| 语音403 | 核对同一项目的语音合成2.0开通状态、音色权限、密钥与额度 |
| 测试音频412 | 检查台词后准备缺失音频；测试模式不会自动生成 |
| 准备计划409 | 台词、分句或音色已变化，重新检查后再准备 |
| 缓存不可读写 | 确认数据库与 data 目录权限；先保留现有文件，排查后再决定恢复方式 |
| 没有密钥但语音开关可用 | 缓存播放能力可用，不代表可以生成新音频 |
| 换图后仍是旧人物 | 检查固定 WebM / MP4 是否仍存在，视频优先于图片 |

`setup.ps1` 结束提示仍泛称 `API_KEY`；实际字段以 `local_config.example.py` 的两项名称为准。这是待整理的启动提示，不代表第三种密钥配置。

## 6. 两台电脑与 Git 交接

新电脑按 README 单独创建环境、配置密钥和快捷方式，不复制旧的 `.venv`。Dify 画布配置、浏览器会话编号和本机数据库不会因拉取代码而同步。

开始前：

```powershell
git status --short
git pull --ff-only
```

先确认本机改动是否已妥善保存。结束时检查差异，只暂存属于本次工作的文件，再提交和推送；另一台开始前拉取。

```powershell
git diff --stat
git diff
# 按实际改动选择文件，例如：
git add README.md docs/ARCHITECTURE.md docs/API.md docs/DEVELOPMENT.md docs/STATUS.md AGENTS.md
git diff --cached --stat
git commit -m "整理项目开发文档"
git push
```

如果拉取失败或两台都改过，保留双方内容后处理合并，不使用 reset --hard 或强制推送覆盖。不要使用 `git push --mirror` 上传本机内部快照。

两端 `git rev-parse HEAD` 相同且 `git status --short` 无输出，才说明已跟踪文件版本一致；不能据此认为环境、密钥和缓存相同。

音频缓存迁移：关闭两台后端，新电脑已有数据库时先备份，再把源电脑 `data/cache.sqlite3` 复制到目标同名位置。不合并数据库，不复制仍在写入的文件。缓存里包含朗读文字和音频，但没有密钥；Git 默认不上传它。
